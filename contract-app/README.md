# Локальная подготовка договора

Отдельное Windows-приложение `contract-app`, версия 0.1.3. Создаёт два редактируемых Word-документа: договор и согласие на обработку персональных данных. Данные хранятся локально. Файлы CRM не используются для формирования документов.

## Запуск и сборка

Из папки `D:\contract-local\contract-app`:

```powershell
npm install
npm start
npm test
npm run dist
```

При установке зависимостей нужен интернет. Сетевые запросы самого приложения заблокированы.

Сборки Windows x64 находятся в `contract-app/release`:

- `Local-Contracts-0.1.3-portable.exe` — запуск без установки и npm.
- `Local-Contracts-0.1.3-setup.exe` — установщик.

Для обновления исходников закройте приложение и выполните:

```powershell
cd D:\contract-local
git switch feature/local-contract-app
git pull --ff-only origin feature/local-contract-app
cd contract-app
npm install
npm start
```

Если Git сообщает о локальных изменениях, сохраните их перед обновлением.

## Ввод и черновик

Форматирование при вводе и вставке: серия паспорта `00 00`, оба телефона `+7 112 299 33 88`, код подразделения `222-333`, сумма `1.950.000 р.`. Можно исправлять значения в середине и удалять цифры возле разделителей. Фокус переходит в первое поле следующего шага.

Хранится один текущий черновик. «Новый договор» очищает его после подтверждения; телефон менеджера сохраняется. Созданные Word-файлы остаются в выбранных пользователем папках. Ошибки и сообщения об успешном сохранении выводятся на странице.

## Документы

Договор использует прежний `templates/contract.docx`: его текст, оформление и генератор не изменены. Предлагаемое имя файла: `№123_Договор_Имя_Отчество_Фамилия.docx`. Из номера и ФИО удаляются запрещённые Windows символы; очень длинное имя ограничивается 185 символами вместе с расширением. ФИО в форме вводится в порядке «Фамилия Имя Отчество».

Согласие создаётся из `templates/consent.docx`; `templates/consent.pdf` сохранён как исходный образец. Основной текст перенесён из PDF без изменения слов, с нормализацией пробелов и переносов. Автоматически заполняются только верхние ФИО, паспорт и адрес. Выбор «согласие/несогласие», нижние полные ФИО, подпись и вся дата, включая год, оставлены для заполнения от руки. Для ФИО и подписи предусмотрены две разнесённые строки.

Для воспроизводимого создания и проверки шаблона разработчик может выполнить `scripts/build-consent-template.py` и `scripts/verify-consent-source.py` в среде с `python-docx` и `pypdf`. Самому Windows-приложению Python и Microsoft Word для генерации DOCX не нужны.

## Проверка версии 0.1.3

- `npm test`: 21 проверка, включая DOCX, имя файла, обязательные поля, отмену/ошибки сохранения, длинные данные и отсутствие данных предыдущего вымышленного клиента.
- Текст основной части согласия автоматически сверен с исходным PDF. Шаблон и генератор договора не изменены.
- Согласия с обычными и длинными ФИО, органом выдачи и адресом отрисованы Microsoft Word и просмотрены полностью: оба занимают одну страницу, текст не перекрывается, поля для ручного заполнения свободны. Договоры также проверены: 7 страниц с обычными данными и 8 с длинными; дополнительная страница — результат переноса в неизменённом шаблоне.
- Portable и приложение, извлечённое из установочного пакета, запущены в отдельных тестовых профилях. Через реальные renderer/IPC-обработчики созданы оба документа для обычных и длинных данных. Во время этих автоматических проверок только системный выбор пути заменён тестовым обработчиком. Содержимое OOXML сравнивается с визуально проверенными документами.
- В portable проверены события мыши/клавиатуры, форматирование полей и суммы, редактирование, просмотр и восстановление черновика. В настоящем системном диалоге согласия проверены имя `Согласие.docx` и фильтр Word; автоматическое нажатие кнопки сохранения средствами Windows Automation недоступно. Установка поверх существующего приложения не выполнялась.

Все проверки выполняются на вымышленных данных. Примеры созданных документов, тестовые профили и EXE хранятся только в игнорируемой папке `release` и не отправляются в Git.
