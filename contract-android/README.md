# Договоры — Android

Отдельное приложение Android 8.0 и новее. Windows-приложение и CRM не изменены.

## Использование

Пять шагов ввода работают без интернета. Черновик хранится только внутри приложения на телефоне; резервное копирование отключено. В конце создаются договор и согласие в DOCX. Под каждым готовым файлом есть кнопка «Переслать»: она открывает системный выбор приложения для отправки. Пользователь сам выбирает получателя и подтверждает отправку.

«Новый договор» после подтверждения удаляет данные и документы предыдущего клиента, сохраняя телефон менеджера. Хранится один черновик и не более одного готового документа каждого вида. Уже отправленные копии находятся в выбранном пользователем приложении.

## Сборка

Node.js, JDK 17+ и Android SDK Platform 35 необходимы для сборки. На рабочем компьютере используются JDK D:\Android Studio\jbr и SDK C:\Android\Sdk. Новые кэши Gradle и файлы проекта размещаются на D: внутри этой папки.

Первый запуск: npm ci. Для нового независимого ключа запустить scripts\create-signing.ps1 только один раз. Для обновлений использовать существующий ключ, не создавать новый.

Сборка: powershell -ExecutionPolicy Bypass -File scripts\build.ps1

Готовый APK копируется в корень проекта и release\Local-Contracts-Android-1.0.2.apk. Открыть APK на телефоне и подтвердить установку.

Сохраняйте .signing\ и signing.properties в защищённом месте: они нужны для выпуска обновлений с той же подписью. Эти файлы, APK, кэши и локальные результаты проверок исключены из Git.

## Документы и проверки

web/vendor и web/templates содержат точные копии проверенных генераторов и шаблонов Windows из коммита c7d0aca5ab773eefd7cba03deeba0e3f17b42676. Контрольные суммы записаны в provenance.json. Для осознанного обновления из соседней папки contract-app: npm run sync:windows.

npm test проверяет контрольные суммы, форматы полей и совпадение всего содержимого OOXML с Windows для обычных и длинных вымышленных данных. Тест OfflineFlowTest на эмуляторе проверяет создание обоих DOCX без интернета, системное меню отправки, доступ к файлу по временному content URI, восстановление черновика и очистку предыдущего клиента с сохранением телефона менеджера. Тест запрещает запуск на физическом телефоне. Дополнительно выполняется Gradle lintRelease.

Релиз не включает тестовые данные и не запрашивает разрешение INTERNET. Отладка WebView отключена в release. Файлы выдаются через закрытый FileProvider с временным разрешением чтения.

Исправление Android 1.0.2: только у значения КПП убран отрицательный отступ -567 twips. Текст и остальные части шаблона неизменны; sync:windows повторно применяет это исправление.
